## 0. Mission

Build **IPsecScope**: a working, passive IPsec PCAP/PCAPNG analyzer with a FastAPI backend, React dashboard and report generator. It must parse IKEv1/IKEv2/ESP/AH/NAT-T with **our own parser**, assess security via YAML rules, score risk deterministically, show packet-level evidence, and generate reports.

## 1. Non-negotiable rules

1. **Read the entire SRS first.** If something is ambiguous, choose the simplest interpretation consistent with the SRS, record the decision in `docs/DECISIONS.md`, and continue. Do not stop to ask unless blocked by a missing credential or an impossible requirement.
2. **No fake/demo-only application.** The analysis must really parse the uploaded file. **Never hard-code findings, scores, sessions, charts or sample data into the backend or frontend** to make screens look populated. The only permitted sample data lives in `tests/fixtures/` and is used by tests/demo scripts that upload through the real API.
3. **Honesty over appearance.** If a feature cannot be implemented reliably, mark it `partial` or `not_implemented` in `analyzer/capabilities.py` (served by `GET /capabilities`, FR-85) and show it in the UI. Never present heuristics as facts: heuristic results carry `confidence < 1.0` and a `heuristic: true` flag.
4. **Never claim to decrypt traffic**, identify ESP ciphers, detect PFS, or read IKE_AUTH/Quick Mode content without keys. Encrypted regions are `not_observable` (FR-34, FR-49).
5. **Do not wrap Wireshark.** The core parser must not call tshark/pyshark. tshark is allowed only in tests (cross-validation) and must be skippable (`pytest.mark.skipif(not shutil.which("tshark"))`).
6. **Security by construction:** no `eval/exec`, `yaml.safe_load` only, no shell with user-controlled strings, bounds-checked parsing, UUID file names, escaped output (React escapes by default; Jinja2 `autoescape=True`).
7. **ML honesty:** implement ML only as specified (SRS §11). If no trained model file exists, the ML module returns `unavailable`. Do not ship a model trained on random/synthetic-noise data to "make it work". The training script must use captures generated by the lab/dataset generator and write evaluation metrics to `docs/ml-evaluation.md` with the caveat text from SRS §11.4.
8. **Keep `analyzer/` free of web dependencies** (no FastAPI/SQLAlchemy imports).
9. **Constants from registries:** IKE/IANA numbers in `analyzer/ike/constants.py` must match the IANA IKEv2 and IKEv1 (ISAKMP/IPsec DOI) registries; if offline, use the values in §6 below and add a `# verify against IANA` comment. Unknown IDs are rendered as `UNKNOWN(<n>)`, never guessed.
10. Work in the order of §9. After each task: run the test suite, fix failures, commit with message `TASK-xxx: …`.

## 4. Core data contracts (`analyzer/models.py`, Pydantic v2)

```python

class DecodedPacket(BaseModel):

    num: int; protocol: Literal["IKE","ESP","AH"] = "IKE"; transforms: list[IkeTransform]

class IkeMessage(BaseModel):

    spi_i: str; spi_r: str; direction: Literal["i2r","r2i"]
    payload_types: list[int]; encrypted: bool
    proposals: list[IkeProposal] = []; ke_group: int | None = None; ke_len: int | None = None
    nonce_len: int | None = None; notifies: list[IkeNotify] = []; vendor_ids: list[str] = []
    nat_detection: list[str] = []; v1_id: dict | None = None; v1_hash_len: int | None = None
    anomalies: list[str] = []; raw_header_hex: str; raw_excerpt_hex: str   # ≤ 64 bytes of the relevant payload

    retransmissions: int; ke_retries: int; aggressive_mode: bool

class FlowSeqStats(BaseModel): max_seq: int; gaps: list[tuple[int,int,int]]; duplicates: int; reorders: int; wrap_near: bool

class IpsecFlow(BaseModel):
    id: str; proto: Literal["esp","ah"]; src: str; dst: str; spi: str; encap: Literal["raw","natt"]
    first_ts: float; last_ts: float; packets: int; bytes: int; seq: FlowSeqStats
    null_suspected: bool = False; null_confidence: float | None = None; inferred_mode: str | None = None
    paired_flow_id: str | None; linked_ike_session_id: str | None; link_confidence: float | None
    sample_pkt_nos: list[int]

class Facts(BaseModel):
    capture: dict; protocol_stats: dict; sessions: list[IkeSession]; observations: list[Observation]
    flows: list[IpsecFlow]; windows: list[dict]; unsupported: list[str]; warnings: list[str]

class Evidence(BaseModel):
    packet_no: int; ts: float; message: str; field_path: str; raw_value: Any; decoded: str | None; hex_excerpt: str; note: str | None

class RawFinding(BaseModel):
    rule_id: str; origin: Literal["rule","detector","ml"]; category: str; title: str
    explanation: str; why_this_matters: str; impact: int; likelihood: int; confidence: float
    evidence: list[Evidence]; affected_sessions: list[str]; count: int = 1
    references: list[str]; mitre: list[str]; recommendation_id: str | None; params: dict; override_severity: str | None = None

class AnalysisResult(BaseModel):
```

## 5. Key algorithms (implement exactly; unit-test each)

### 5.1 Classification (`classify/classifier.py`)
```
for pkt in decoded:
  if ip_proto == 50: ESP(raw)
  elif ip_proto == 51: AH
  elif ip_proto == 17:
     if dport in (500,4500) or sport in (500,4500):
        p = pkt.payload
        if len(p)==1 and p[0]==0xFF and 4500 in (sport,dport): KEEPALIVE
        elif 4500 in ports and p[:4]==b"\x00\x00\x00\x00": try IKE(p[4:], natt=True)
        elif 4500 in ports and len(p)>=8 and p[:4]!=zeros: ESP-in-UDP (spi=p[:4])
        elif 500 in ports: try IKE(p, natt=False) [also tolerate marker]
     (optional FR-18) else try IKE header validation with conf<=0.6
```
`try IKE` = validate `len>=28`, version major in {1,2}, exchange type in known set for that version, header length ≤ len(payload) and ≥ 28. If invalid on port 500/4500, count as `malformed_ike_candidate` (feeds IKE-PROTO-001), not silently dropped.

### 5.2 IKE header (28 bytes)
`spi_i[8] spi_r[8] next_payload[1] version[1] (major=v>>4, minor=v&0xF) exch_type[1] flags[1] msg_id[4] length[4]` (big-endian).
- IKEv2 flags: `I=0x08`, `V=0x10`, `R=0x20` (R set ⇒ response; I set ⇒ sent by original initiator). Direction i2r iff I flag set.
- IKEv1 flags: `E=0x01` (encrypted), `C=0x02`, `A=0x04`. Direction: sender of first message seen for that cookie pair is initiator.

### 5.3 Payload walk (v2)
Generic header: `next[1] critical|reserved[1] length[2]`. Loop while `next != 0`: require `length >= 4` and `offset+length <= msg_len`; dispatch by *current* payload type; record anomalies instead of raising. `SK(46)`/`SKF(53)` ⇒ stop, mark `encrypted=True`. SA payload → Proposals: `last_or_more[1] reserved[1] length[2] proposal_num[1] protocol_id[1] spi_size[1] num_transforms[1] spi[spi_size] transforms…`; Transform: `last_or_more[1] reserved[1] length[2] type[1] reserved[1] id[2] attributes…`; attribute TV format when high bit of 16-bit type set: key length is attribute type 14 (0x800E) value.

### 5.4 Payload walk (v1)
Generic header `next[1] reserved[1] length[2]`. If header flag E set ⇒ payloads after header are encrypted: record `encrypted=True`, parse nothing. SA: `DOI[4] situation[4] proposals…`; Proposal: `next[1] res[1] len[2] num[1] protocol[1] spi_size[1] num_transforms[1] spi…`; Transform: `next[1] res[1] len[2] num[1] id[1] res[2] attributes`. Attributes: if `type & 0x8000` ⇒ TV (value = next 2 bytes) else TLV (length[2] then value). Attribute classes: 1 encryption, 2 hash, 3 auth method, 4 group description, 11 life type, 12 life duration, 14 key length.
Aggressive Mode (exchange 4) msg1: SA, KE, Nonce, ID; msg2: SA, KE, Nonce, ID, HASH (all clear). Record `v1_id` (type, redacted value) and `v1_hash_len`. Main Mode (exchange 2): messages 1–4 clear (SA, SA, KE+Nonce, KE+Nonce); 5–6 have E flag set.

### 5.5 Session reconstruction (`ike/sessions.py`)
- v2 key: `(initiator_ip, spi_i)`. On first message with `spi_r == 0` create session. On first response with non-zero `spi_r`, set it. Retry after COOKIE or INVALID_KE_PAYLOAD (same `spi_i`, same initiator) ⇒ same session; increment `ke_retries`/`cookie_used`.
- v1 key: `(cookie_i, cookie_r)`; messages from initiator with `cookie_r == 0` pair with the next response.
- Retransmission: same session, direction, exchange type, message id and payload hash seen before ⇒ `is_retransmission=True`, counted, excluded from rate statistics except flood detection.
- Outcome: `failed_notify` if error-class notify (type < 16384) from responder in SA_INIT/Main Mode; `established_observed` if v2 IKE_AUTH response seen (encrypted) or v1 Main Mode msg 6/Quick Mode seen; `unanswered` if only initiator messages; `incomplete_capture` if responses seen without request or flow ends mid-exchange; else `unknown`.
- IKEv2 `selected` = the single proposal in the responder's SA_INIT response; `offered` = proposals in initiator's SA_INIT. Same for v1 Main Mode msg 1/2 and AM msg 1/2.

### 5.6 ESP tracking (`esp/tracker.py`)
Per flow key `(src,dst,spi,encap)`; first 8 bytes (UDP-encap: after UDP header) = `spi[4] seq[4]`. Seq logic per flow: if `seq == last+1` ok; `seq > last+1` ⇒ gap `(last+1, seq-1, pkt_no)`, `last=seq`; `seq == last` or seen in recent-window set (size 1024) ⇒ duplicate; `seq < last` and not seen ⇒ reorder. `wrap_near = max_seq > 0xFFFFFF00`. Keep only: counters, ≤ 200 gap records, size histogram (16 bins), inter-arrival min/mean/max/std, ≤ 500 downsampled `(ts,seq)` points, and first 50 packet prefixes (64 bytes) for the NULL heuristic. Never store full payloads.

### 5.7 ESP-NULL heuristic (`esp/null_heuristic.py`)
For up to 50 sampled packets of a flow: `b = payload_after_esp_header`; candidate if `len(b) >= 20`, `b[0] >> 4 == 4`, `ihl = (b[0] & 0xF)*4 >= 20`, `total_len = u16(b[2:4])` with `ihl <= total_len <= len(b)`, and the IPv4 header checksum over `b[:ihl]` verifies (one's-complement sum == 0xFFFF). Flag flow if ≥ 90% of ≥ 10 sampled packets pass. (A random block passes a checksum test with probability ≈ 2⁻¹⁶ per packet.) Output `null_suspected=True, null_confidence=0.85, inferred_mode="tunnel (inferred)"`. Document the limitation: IPv6-in-ESP-NULL and transport mode are not covered (add as `partial`).

### 5.8 Flood detector (`detectors/ike_flood.py`)
Count non-retransmission IKE_SA_INIT requests (v2 exch 34, I=1,R=0) and v1 Main/Aggressive msg 1 by (source ip, 1-second bucket) and aggregate-per-responder. Raise when `per_source_rps ≥ P` or `aggregate_rps ≥ A` for ≥ `min_duration_s` consecutive buckets. Also compute `response_ratio` and whether responder replies carried KE payloads vs COOKIE notifies (feeds IKE-DOS-002).

### 5.9 Scan detector (`detectors/ike_scan.py`)
Per source: distinct responder IPs on 500/4500 within a 60 s sliding window ≥ 5 ⇒ finding. Per (source, responder): ≥ 5 v1 Main Mode msg-1 each containing exactly one transform and with distinct transform tuples, no msg-3 follow-up ⇒ finding (ike-scan style enumeration).

### 5.10 Declarative rule engine
Targets: `observation`, `session`, `flow` (pydantic models flattened to dicts with dotted paths). Condition grammar:
```
cond := {all: [cond...]} | {any: [cond...]} | {not: cond} | {field: str, op: str, value: any}
ops: eq ne in not_in gt gte lt lte exists contains
```
Evaluation never uses `eval`. Impact resolution: `{default:n}` | `{table: name}` (lookup by `observation.id` or `name` in policy tables) | `{fixed:n}`. Likelihood resolution: `{fixed:n}` | `{from: role}` (selected→5, offered→3). Title/explanation use `str.format_map` with a safe dict (missing keys → empty, never raise). Group by `group_by` keys; merge evidence (max 5 per finding) and sessions; set `count`.
**Offered+selected dedupe:** if the same `(session_id, kind, id)` appears with both roles `offered` and `selected`, emit **one** finding with role `selected` (likelihood 5) and attach the offered evidence as secondary. Rules for hash/PRF/integrity weakness (CRY-INT-001) must match observation kinds `prf`, `hash` (IKEv1) and `integ`.

### 5.11 Scoring (`scoring/risk.py`) — implement per SRS §12.3 verbatim
```python
def risk(impact, likelihood, confidence): return round(impact*likelihood/25*100*(0.5+0.5*confidence), 1)
def severity(r, impact, override): …bands…  # Critical>=85, High>=65, Medium>=35, Low>=15, else Info (impact 0 ⇒ Info)
def posture(findings): P = 100*prod(1-0.6*min(r,95)/100 for severity>=Low); apply caps; grade
```
Include property-based tests: monotonic in each input; bands boundaries exact; posture within 0–100; caps enforced.

### 5.12 Fingerprint for comparison
`sha1(rule_id + "|" + sorted(params))[:16]`, where params are the stable parameter identifiers (e.g., `dh=2,role=selected`), **not** IPs or packet numbers.

## 7. Backend behaviour

- App factory in `backend/app/main.py`; routers under `/api/v1`; CORS from env; security headers middleware; request-size guard for `/analyses` (stream to disk with cap).
- Jobs: `ProcessPoolExecutor(max_workers=WORKERS)`; progress via `multiprocessing.Manager().dict` or periodic DB updates through a queue; on analyzer exception record `error_code/message` (no stack traces to clients; log them server-side).
- Persist result in one transaction; mark `completed` last. On app start: mark `running` as `failed:interrupted`; schedule retention purge.
- Pagination, filtering and sorting server-side for sessions, flows, findings.
- Rate limit uploads (in-memory token bucket per IP; configurable).
- Auth dependency enabled only when `API_TOKEN` set.
- Standard error envelope for every exception (including validation errors).

## 10. Error handling requirements
- Analyzer: typed exceptions; per-packet failures counted, not fatal; fatal only if capture unreadable or limits exceeded.
- Backend: map errors to the envelope; never leak file paths or stack traces.
- Frontend: show envelope `message`; retry button on network errors; failed analysis screen shows `error_code` and `message`.
